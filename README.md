# esp32-scd41-i2c-monitor

ESP32-C3 다중 I2C 디바이스 제어 및 대기질 모니터링 시스템

[프로젝트 시연 화면](Animation5.gif)

1. 프로젝트 개요

ESP32-C3를 메인 MCU로 사용하여 I2C 기반의 환경 센서(Sensirion SCD41)와 디스플레이(SSD1306)를 충돌 없이 제어하고, 실시간으로 이산화탄소 농도와 온도, 습도 데이터를 모니터링하는 시스템입니다. 
단순한 센서 결합을 넘어, 통신 프로토콜의 안정성 확보와 MCU 자원 최적화에 초점을 맞추어 구현했습니다.

사용 기술: C/C++, ESP32-C3, I2C 통신
주요 부품: Geekble Mini ESP32-C3, Sensirion SCD41(이산화탄소 농도 및 온습도 센서), SCD1306(0.91인치 OLED 디스플레이)

2. 하드웨어 핀 맵

하나의 I2C 버스(SDA, SCL)에 복수의 슬레이브 디바이스를 병렬로 연결하여 핀 리소스를 절약했습니다.

SCD41과 SSD1306 모두 SDA핀은 GPIO 4핀에, SCL 핀은 GPIO 5핀에 연결하고 SCD41은 0x62 주소로, SSD1306은 0x3C 주소로 접근했습니다.

3. 핵심 기술 및 구현 포인트

1) I2C 슬레이브 주소 기반 다중 디바이스 제어
두 가닥의 물리적인 선(SDA, SCL)에 센서와 디스플레이가 병렬로 물려있는 구조입니다. 충돌을 방지하기 위해 데이터시트를 참조하여 디스플레이에는 0x3C, 센서에는 0x62의 고유 I2C 주소를 할당하고 초기화했습니다. 이를 통해 하나의 버스 안에서 각 기기를 독립적이고 안정적으로 제어할 수 있는 아키텍처를 구성했습니다.

2) 데이터 무결성을 위한 상태 폴링 구현
SCD41 센서는 측정 주기가 비교적 길어 데이터가 준비되지 않은 상태에서 값을 요청하면 쓰레기 값이 반환 되거나 통신 오류가 발생할 수 있습니다. 이를 방지하기 위해 센서의 상태 레지스터를 먼저 읽어 데이터 준비 여부를 확인('getDataReadyStatus')하는 폴링 방식을 적용했습니다. 신호가 확인되었을 때에만 데이터를 읽어오도록('readMeasurement') 제어하여 시스템의 신뢰성을 높였습니다.

3) 타이머 기반 논블로킹 구조 설계
MCU가 특정 동작을 기다리며 멈춰있는 블로킹함수('delay()') 사용을 배제했습니다. 대신 하드웨어 타이머인 ('millis()')를 활용해 5초 주기로 시간을 비동기적으로 계산하는 논블로킹 로직을 구현했습니다. 이를 통해 센서의 측정 주기 사이클 중간에도 디스플레이 렌더링 등 MCU의 다른 연산 처리가 즉각적으로 이루어질 수 있도록 자원 효율을 극대화했습니다.
